# Luchdom Documentation Ownership

- `README.md`: orientation, supported entry points, bootstrap, and links
- `AGENTS.md`: repository-specific workflow routing, commands, safety, and authority
- `docs/HARNESS.md`: one-iteration behavior, stop conditions, outputs, recovery
- `docs/WORKFLOW.md`: repository-specific use of the three entries and specialist stages
- `docs/DECISIONS.md`: decisions requiring attended authorization and durable reply syntax
- `docs/QUALITY.md`: local definition of done, validation, review, and runtime acceptance
- `docs/LOCAL-DEVELOPMENT.md`: required tools and local bootstrap/runtime commands
- `docs/LINEAR.md`: project issue contract, ordinary states/labels, and autonomous intake
- `docs/AI-TOOLING.md`: installed tool verification and missing-tool recovery
- Module docs: domain-specific architecture, configuration, how-to, runbook, and troubleshooting

Shared cross-tool stage, artifact, clarification, quality, and completion policy belongs only under `$goal-to-delivery` references. Repository docs link it and add project-specific or stricter rules; they do not restate it.
