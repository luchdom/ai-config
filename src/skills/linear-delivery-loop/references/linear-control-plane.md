# Linear selection, decisions, and ntfy control plane

This reference describes the fixture-first SAAS-47 adapter boundary. The package is not part of the public engine-command union and cannot activate the autonomous loop by itself. SAAS-49/52 own integration; SAAS-54 owns attended ntfy configuration and pilot activation. Linear is the durable source for decisions and work state. ntfy is attention-only.

## Configuration and preflight

`tracking-config.schema.json` stores provider identifiers, ordinary state and label identifiers, endpoint allowlists, version bindings, and environment-variable names. It never stores credential values. Linear credentials resolve only from `LINEAR_API_KEY`; optional ntfy values resolve from `NTFY_URL`, `NTFY_TOPIC`, and `NTFY_TOKEN`.

Before selection or provider mutation, `TrackingPreflight` read-verifies the configured workspace, SAAS team, project, owner, ordinary states, labels, repository identity, endpoint, and supervisor version. It validates the resolved ntfy HTTPS host/topic policy and issues a short-lived HMAC-signed attestation bound to the configuration digest, repository identity, supervisor version, owner, provider endpoints, timeout/retry settings, and an opaque engine claim binding. Only the engine-owned issuer key can mint an accepted exact-field attestation; copied, extended, expired, substituted, or drifted attestations fail closed. The mutation facade accepts no registry, claim port, callback factory, or authority object. It supplies the opaque binding to the exact repository-bound `SupervisorEngine`, which executes a closed operation set internally and returns only non-authority results. Production exposes no adapter installer or authority-entry resolver, and its closed-operation methods cannot be replaced on an engine instance. A copied-ID port, caller-supplied authority, initial callback composition, direct authority resolution, or post-attestation replacement therefore fails before local preparation or provider access. Raw fixture composition lives only in isolated test support and is not a runtime authority surface. Selection, claim, request/reply mutation, proposal/failure mutation, and notification entry points verify the attestation with that bound issuer. A missing, mismatched, or ambiguous observation fails closed and creates one composed actionable failure/attention record when appropriate. Provider request, sleep, clock, observation, reservation/worktree authority, and state mutex behavior remain injected for deterministic tests.

`LinearTransport` accepts GraphQL variables, an explicit timeout, and an exact allowed HTTPS `/graphql` endpoint. It rejects redirects and host drift, distinguishes pre-dispatch configuration and read-only HTTP/protocol/GraphQL errors, bounds `429`/`5xx` retries, and requires a non-empty progressing cursor until `hasNextPage` is false. Mutations require a stable operation identity and read-before/write/read-after reconciliation. Every post-dispatch outcome that cannot prove non-application—including malformed JSON, a missing data envelope, GraphQL errors, or a malformed response envelope—is ambiguous and enters readback; it is never blindly repeated.

## WIP and selection

One engine-owned observation adapter requests the complete nested Linear issue shape used by policy, fully paginates to a terminal page with a strictly validated cursor chain, and normalizes each node into one closed issue contract before selection or migration can consume it. Missing issue fields, malformed nested state/labels/parent/project evidence, missing completion flags, missing cursors, repeated cursors, and inconsistent page evidence fail with a domain error before a selection record or report is written. The adapter then combines normalized issues with the supervisor-owned repository reservations, issue-worktree mappings, and recovery state. That observation is combined atomically with pending decisions, publication requests, proposals/failures, and selection claims. Ordinary selection is allowed only when this authoritative snapshot proves no active, pending, protected, or foreign work. The selected candidate and complete snapshot/preflight digests are persisted as a compare-and-set selection claim before control returns, so concurrent selectors cannot both win. The WIP rule is global across `In Progress` and `In Review`:

- Multiple active issues fail closed and create one actionable attention event.
- Manual or semi-autonomous WIP exits quietly.
- Exact autonomous WIP resumes only with matching reservation evidence.
- Only zero WIP permits selection.

Eligibility requires `Todo + autonomous`, the configured repository, a complete achievable code-leaf goal, no parent, no external dependency, and none of `stop`, `external-integration`, `needs-refinement`, or `needs-human`. The fully filtered set sorts by Linear priority, oldest `createdAt`, then numeric issue identifier.

The winner is reread immediately. Before any authority or provider mutation, the persisted selection moves by compare-and-set from `pending` to `in-flight`, binds one operation identity, and records the engine execution owner, lease revision, and expiry. Under that identity, the authority adapter atomically prepares the repository reservation and persistent issue-worktree mapping before the Linear claim. Provider claim is second and readback is third. A process/thread operation fence spans acquisition, provider work, readback, and local commit. Lease expiry alone cannot supersede an active fence; only a crashed process releases its dead-PID ownership for takeover. A process can disappear without running an exception handler at any boundary, so both original and recovery execution owners are durably bound to an owner, lease revision, expiry, and the current fencing generation. Recovery requires exact engine authority proof that the recorded owner is dead or its lease expired. One compare-and-set winner advances the exact operation to the next `recovering` generation, and the engine revalidates both its operation fence and generation immediately before local recovery, provider mutation, every readback, and local commit. A live owner and concurrent contenders remain inert, including after logical lease expiry. If a recovery process crashes after acquisition, local recovery, provider claim, or readback, one later proven-dead/expired generation reconciles from local and provider state without duplicate remote mutation. Ambiguous recovery returns the same generation to `protected`. Terminal outcomes persist the exact result so an identical operation replay returns it while a different operation remains rejected. Recovery never selects a second candidate. Manual/semi selection may remove `autonomous` only after matching authority reconciliation.

## Durable requests and replies

`ControlPlaneStore` persists strict per-collection schema-validated records beneath the supervisor-owned state home using atomic replacement and the shared supervisor mutex. Durable logical IDs bind stable owner, configuration digest, repository identity, source identity, provider evidence, consumption markers/timestamps, attention links, notification attempts, and selection snapshots; they do not depend on a short-lived attestation issuance. IDs and cross-field semantics are recomputed during every load, so forged or inconsistent disk state fails closed while a fresh valid attestation can resume an existing record after TTL expiry.

- Material product, security, or cost ambiguity creates one `needs-human` decision with options, consequences, a recommendation, and `DECIDE <decision-id> <option-id>`. Only a newer exact reply by the configured owner is consumed once. Decisions never create speculative child work.
- Incomplete goals propose `Backlog + needs-refinement` and remain quiet.
- Deferred provider work proposes `Backlog + external-integration` and remains quiet.
- A follow-up is permitted only for one separately achievable, independently actionable external prerequisite.
- Publication refusal retains the complete ordinary-state, autonomous-label, WIP, reservation, worktree, branch, optional PR, operation/head, and attestation snapshot. Stable/exhausted refusals add `blocked + needs-human`; success clears those stop labels. Only `RETRY-PUBLICATION <operation-id> <head-sha>` from the configured owner, newer than the request and after complete independent reconciliation, yields one SAAS-48 retry approval. The control plane records/authorizes the retry; the separate injected fixture-first [publication engine](publication.md) executes it.

## Attention and quiet states

An attention event is emitted exactly once for each material decision, independently actionable external blocker, multiple-WIP reconciliation failure, stable/exhausted/ambiguous publication refusal, or actionable worker/preflight failure. Issue-contract proposals such as `needs-refinement` and deferred external-integration work remain quiet. Validation enforces the complete source-to-attention mapping, exact cardinality, and equality of issue, timestamp, link, and summary fields. Empty queues, held leases, manual WIP, routine stages, and failures demonstrably transient and within retry budget also remain quiet.

`NtfyTransport` accepts only allowed HTTPS hosts, refuses redirects, uses a stable provider idempotency key, bounds retries, and returns a persistable outcome. Before sending, the control plane atomically creates one durable in-flight attempt. Concurrent or replayed callers do not publish again; an interrupted in-flight attempt remains `recovery-required` for attended reconciliation instead of guessing whether delivery occurred. Terminal delivery/failure is compare-and-set onto that attempt. Notifications contain a redacted summary and link to the single Linear request. Delivery failure stays visible in the redacted control-plane status; it never replaces Linear or creates a second request.

## Migration, status, and rollback

`ControlPlaneStore` accepts only the explicit legacy `1.0` to current `1.1` state migration. For each legacy publication request, it backfills `lastConsumedReplyTimestamp` from `sourceTimestamp` while the request is pending, or from the active `consumedReplyTimestamp` while authorized. It then validates the complete `1.1` contract and atomically persists one revision bump under the shared supervisor mutex; subsequent reads are idempotent. Malformed `1.0`, unknown versions, and current `1.1` state with a missing or tampered watermark fail closed without rewriting the file, preserving the evidence for attended reconciliation.

The migration report consumes the same engine-owned, terminally proven pagination observation as selection and performs no mutation. It refuses caller-provided issue iterables, incomplete pages, and repeated cursors. It lists every issue, all rejection reasons, current metadata, and deterministic proposed ordinary-state/label changes while retaining unrelated labels. Operators must review the report before any later attended migration.

Status composition adds only record IDs, issue IDs, kinds, states, links, and redacted summaries. It omits record data, credentials, and authority references.

Live activation is intentionally unavailable. Roll back with a normal reviewed change; preserve supervisor state, operation evidence, reservations, and worktrees. Never manually delete a state home or protected worktree to recover a provider ambiguity.
